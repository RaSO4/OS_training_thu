## A100 (cpu9)
- scalar int8 closed loop: success=0.9967, steps_per_sec=859.0, forward 27,488 ticks/step.
- vector int8 modelbench: ticks_per_call=1747.8, samples_per_sec=13730.0;
  prints valid results, then exits with SIGSEGV at VA 0xffffff0000000000 (EXECUTE).
- vector int8 closed loop / 4 processes: wild-PC SIGSEGV (EXECUTE) at random VAs.
- Interpretation: the A100's plain-RVV user path is not stable under preemption even
  with per-task vector state.  This matches the k3x-HERA-RT note about occasional
  illegal stval on A100; its intended path is IME, not general RVV.
  A100 scalar (no user V instructions) is stable.

## Kernel effect
- Before: 8-process X100 vector int8 crashed (IllegalInstruction at vwmacc, then wild PC).
- After: 8/8 processes complete, 99.67% success.  The fix was missing
  vtype/vl/vstart in the vector context; reading them before the temporary
  e32/m8 save layout is essential.
- In-process threads still crash at VA 0x10/0x0 (StarryOS thread/TLS startup);
  multi-process is the stable scaling path.

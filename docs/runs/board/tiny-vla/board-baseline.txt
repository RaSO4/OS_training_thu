## Notes / limitations
1. `sched_getcpu` (syscall 168) returns -14 on StarryOS, so the programs print cpu=-14.
   `sched_setaffinity` (122) does not report an error; multi-process scaling and
   A100-vs-X100 timing differences indicate pinning is effective.
2. Any multi-threaded run of the VLA binary (threads=2/4/8, pinned or unpinned,
   vector or scalar) crashes immediately with SIGSEGV at VA 0x10 (READ) or 0x0
   (WRITE). This is a StarryOS thread/TLS startup issue, not the RVV context bug:
   the scalar build (no V instructions) crashes identically. Single-process
   multi-env batch mode and multi-process pinning are the stable paths.
3. The vector build on A100 completes the benchmark and prints valid results,
   then exits with code 139 during teardown. Numbers are usable with that caveat.
4. The matrix multiply is the bottleneck: feature building is ~50 ticks/step vs
   ~6600 ticks/step of MLP forward on X100 batch=8.
5. Vector build is ~2.9x faster than scalar at batch=1, but at batch=8 the scalar
   build catches up (~6600 vs ~6800 ticks/sample). The current auto-vectorized
   batch loop does not exploit RVV well; loop-order/quantization work is next.

## Comparison
# int8 X100 closed loop 11839.9 vs f32 v2 8848.7  = 1.34x
# int8 X100 closed loop 11839.9 vs v1 3461.1      = 3.42x
# int8 modelbench A100 13962.5 vs f32 A100 1784.9 = 7.82x; A100 == X100 with int8.

## Interpretation
- int8 is the right kernel for this workload: it halves weight bandwidth, uses
  vwmacc, and removes the f32 A100 penalty.
- The remaining instability is the kernel vector-context bug, not the model:
  any multi-process/vector workload can corrupt v0-31 because the scheduler
  neither saves nor restores vector registers.  Fix is in axcpu TaskContext
  (v0-31 + vcsr, per-task state).
